🧬 CÉLULA COMERCIAL FINANCIERA
Plaintext
┌────────────────────────────────────────────────────────────────────────┐
│                   ALPHA OS: MOTHER CHECKOUTQUANTA                      │
│                                                                        │
│   1. LiveEdgeQuanta (ENTRADA / RELEVO)                                 │
│      └─ Pasa el productQuantaHash y la reserva de stock a Checkout.    │
│                                                                        │
│   2. MotherCheckoutQuanta (MOTOR ACID / PROCESADOR)                    │
│      └─ Procesa cobro en <800ms, valida idempotencia y registra        │
│         la transacción con precisión Decimal(19,4) emitiendo txHash.   │
│                                                                        │
│   3. Downstream Triggers (POST-VENTA)                                  │
│      └─ Emite eventos desacoplados hacia Fulfillment y Cashback.       │
└────────────────────────────────────────────────────────────────────────┘
🛠️ Operativa Práctica de la Célula
LiveEdgeQuanta (El Relevo): Sirve la vitrina ultra-rápida en memoria/RAM. Cuando el cliente hace clic en "Comprar", transfiere el productQuantaHash y el token de reserva hacia MotherCheckoutQuanta.
MotherCheckoutQuanta (El Guardián ACID): Procesa el cobro en la pasarela externa, valida la clave de idempotencia en Layer 0, descuenta el stock y graba el registro de auditoría en la tabla de transacciones bajo un txHash inmutable con precisión Decimal(19,4).
Downstream Triggers: Al confirmarse el txHash, dispara webhooks en segundo plano hacia FulfillmentQuanta (logística) y CashbackQuanta (incentivos).

🟧 WRAPPER 1: BACKEND ACID Y TYPES (Para pegar en el IDE)
Plaintext
PROMPT PARA IDE: Construir Módulo Backend, DTOs y Servicios para "MotherCheckoutQuanta"

Actúa como Arquitecto Principal de Software y Guardián ACID. Implementa la infraestructura Backend para el módulo 'MotherCheckoutQuanta' en NestJS, Prisma y Zod bajo las siguientes reglas estrictas:

1. MODULARIDAD Y DTOs:
   - Crea el módulo NestJS 'MotherCheckoutQuanta' con su correspondiente Controller y Service.
   - Define Schemas de validación Zod para las peticiones de checkout especificando: payload de cobro, 'idempotencyKey' y el pasaporte obligatorio 'productQuantaHash' del producto a adquirir.

2. FINANCIAL PRECISION & ATOMICIDAD ACID:
   - PROHIBIDO el uso del tipo 'Float' o 'Number' de JS para importes monetarios, precios o tasas.
   - Configura y maneja todos los campos monetarios utilizando estrictamente 'Decimal(19,4)' en Prisma y la librería Decimal.js en el servicio.
   - Envuelve todo el proceso de registro contable en la tabla de transacciones, deducción de inventario y actualización de orden dentro de una transacción atómica inquebrantable usando 'prisma.$transaction()'. Si ocurre cualquier fallo de red o DB, ejecuta rollback total.

3. IDEMPOTENCIA Y LATENCIA (LAYER_0_DETERMINISTIC):
   - Corre en Capa 0 (cómputo determinista $0.00 USD). Tiempo total de ejecución objetivo: <800ms.
   - Implementa un mecanismo de idempotencia en memoria/caché mediante la clave 'idempotencyKey'. Si entra un duplicado por red, retorna la respuesta previa en <100ms sin re-ejecutar transacciones en la base de datos.
   - Implementa Rate Limiting estricto utilizando '@nestjs/throttler' para blindar el endpoint contra abusos y ataques de Carding.

4. ZERO-BREAK & REGISTRO DE TRANSACCIÓN:
   - No alteres esquemas legacy existentes. El módulo debe ser 100% retrocompatible.
   - Genera un hash criptográfico inmutable de auditoría de transacción ('txHash') al completar la operación contable y vincúlalo al 'productQuantaHash' recibido.
